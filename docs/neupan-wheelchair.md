# NeuPAN 轮椅适配

先安装 NeuPAN 的 Python 3.8 兼容分支，再训练一次与轮椅轮廓匹配的 DUNE 模型。模型权重放在工作区外，通过 launch 参数传入：

```bash
roslaunch smart_wheelchair_safety neupan_wheelchair.launch \
  dune_checkpoint:=/models/wheelchair_dune.pt
```

节点合并 `/unified_scan_left` 和 `/unified_scan_right`，视场分别为 `-30°～170°` 与 `-170°～30°`，并使用 `/shared_control/reference` 作为 naive initial path。`/shared_control/reference_speed`（`TwistStamped`）与路径使用相同时间戳，提供该路径的线速度上限；路径与速度未配对时不产生有效 action。输出为 `/neupan/cmd_vel`、`/neupan/plan` 和 `/neupan/status`。

NeuPAN action 只有在输入和参考路径新鲜时才会被统一控制器采用；最终速度仍经过独立制动检查。缺少 Python 包、配置或 checkpoint 时节点会发布零 action，现有门洞/延墙控制继续工作。

已检查扫掠净空的窄门路径由门洞控制器连续执行，包括对正、穿门和车尾清门，避免两套
曲率控制在窄门内交替接管。NeuPAN 用于其他辅助行驶模式；这是混合控制，并非纯 NeuPAN
过门。远处对正阶段目标速度为 0.35 m/s；距离门平面 1.6 m 内将目标降至 0.15 m/s，
穿门和车尾清门阶段保持这一目标。目标变化时先回收加速度，实际速度可能短暂高于新目标；
固定最高速度与最终制动检查仍独立限制输出。窄门制动检查为整个有效里程计延迟窗口预留余量，常规加速也预留请求速度对应的
状态不确定性；低速脱困继续使用原有停止基准与严格分离检查。
沿墙、开口转弯和前墙停车还会在加速前预留完整里程计时效及下一控制周期的停车余量，
因此近墙速度可能低于空旷区域速度；到达限速前提前回收加速度，避免指令突然截断。
`/shared_control/status` 的 `planner_source` 记录实际选择的动作来源（`neupan`、
`door_follower`、`local_follower`、`recovery`、`joystick` 或 `stop`）；安全检查仍可将
选中的动作降速或清零。排查 `stale_input` 时可查看同条状态中的 `input_age_s`。
仿真使用 ROS 时钟检查里程计时间戳和接收年龄，两者仍受默认 0.10 s 时限约束；
另保留至多 0.25 s 的墙钟接收截止。非仿真按墙钟检查默认 0.10 s 接收时限。
超过实际时效的数据仍触发保护停车，不能保证仿真调度停顿时连续行驶。
里程计时间戳检查和摇杆、扫描失联停车在两种模式下都保留。
里程计接收线程仅保存最新帧，不等待控制锁；控制回调在锁内消费最新帧，并保留真实接收时间，
避免旧帧积压。短暂摇杆失联仍立即停车，但在现有失联宽限内保留已检查的门路径；
恢复新鲜同向输入后重新检查并续行，主动松杆、反推和关闭辅助仍会取消过门。
摇杆接收同样不等待控制锁，并独立锁存取消输入；即使随后立即前推，也先撤销旧路径与
模型动作授权，再等待新参考路径，接收时间不会在消费时刷新。
过门目标速度若已通过当前状态和下一周期停车的两项检查便直接采用，否则执行原有速度搜索，
减少常态控制计算量而不放宽安全约束。
仿真将 Gazebo 的 ROS 时钟发布频率设为 100 Hz，避免每个 Python 节点处理每秒千次时钟回调；
物理步长、传感器频率和控制周期保持原配置。

窄门检测使用门平面附近至少三个不同激光返回点收紧可见内缘，避免只拟合门框正面而
高估净宽；该修正只能缩小开口，并经过原有两帧确认。多个门都符合摇杆方向时，先处理
最近的门。直接对正路径检查全部障碍点及姿态间扫掠，预留至少 6 cm 净空；不足时在尚有
转向空间的位置选择已检查的分段对正路径，避免行进后才陷入制动余量不足的等待。
同一窄门在稳定平面和朝向下出现被原开口包含的更窄观测时，可替换早期过宽估计，
同时撤销旧路径与旧规划结果。车尾清门依据已观测的门框后表面、车身后缘在门法向上的
完整投影及 4 cm 余量判断；切换下一目标和完全恢复摇杆转向共用这一条件。

局部规划与 NeuPAN 动作使用保留真实接收时间的最新消息槽，消费时同时检查参考路径授权和
动作时效，避免控制锁排队将新动作延迟成超时。取消输入先撤销旧授权，旧动作不能重新获权。
仿真中，NeuPAN 与局部跟踪器的输入、统一控制器的规划动作使用各自实际接收时记录的
ROS 时间检查年龄，保留原 0.25 s 有效期；原参考时间戳和授权匹配检查继续执行。
里程计和扫描时间戳只允许与控制器原有规则一致的至多 0.05 s 仿真时钟偏差，参考和动作
不增加未来时间容差。非仿真仍使用原墙钟接收年龄。
独立墙钟线程在仿真时钟连续 0.25 s 不推进时撤销动作授权并持续发布零速度。
监测线程获取控制锁后才读取当前时间，避免使用排队前的旧快照误判冻结或倒退。
时钟恢复后只接受恢复边界之后到达的运动心跳；旧取消输入仍可撤权，但不能恢复运动权限。
该线程不能在整个虚拟机暂停时执行，因此不构成硬实时承诺。
状态中的 `control_stamp_s` 与 `control_dt_s` 分别记录实际控制时刻和使用的计算周期，
可用于区分控制周期与状态消息接收延迟；冻结停车状态的计算周期为零。

高速行进时，新门捕获同时检查实际输出弧线是否指向开口。已确认门意图但尚未准入时，
使用持续新鲜的摇杆弧线作为普通辅助参考，将目标平滑降至既有的 0.35 m/s 对齐速度，
避免沿墙参考继续带离用户选择的门。准备状态不代表门路径已检查；输出与实测速度满足准入条件，
且当前输出与完整等待停稳预估通过原有完整里程计年龄制动检查后才提交门任务。同一持续门意图不会因
减速中的瞬时曲率偏差反复解除限速。准入比较包含原平滑算法离散死区上界 0.003125 m/s，
发布的目标仍为 0.35 m/s。等待预估首步使用当前实测运动，后续按恒定命令积分并假设理想跟随，对冻结点云逐步执行原制动检查，
最多 80 步；未能停稳或任一步不通过则保持准备状态，继续按当前辅助参考行驶后重新评估。
预估使用独立状态，不写回实际速度、加速度或点云；它不等同于真实未来扫描，也没有保证实际跟随无延迟。
此检查不是未来所有状态的安全保证，最终独立制动检查持续执行。

门前等待与准入预估共用减速计算。原地对齐达到角度容差后，先平滑将角速度及角加速度
归零，并确认实测角速度小于 0.01 rad/s，再恢复平移。正常辅助模式的线、角速度目标改变时
允许尚未回收的加速度短暂延续，避免直接截到新目标造成顿挫；接近固定物理速度边界时提前
回收加速度。门路径的平移速度也使用同一计算，避免接近分段转向点时突然截断速度。
对正、穿门和车尾清门的非原地旋转阶段，对已有路径给出的角速度目标限加速度及 jerk，
保留真实输出角加速度以连续衔接。原地旋转也使用同一双轴连续计算，避免角度目标变化时
硬截断角速度；门前等待与到位后的停稳继续使用原有停止计算。
这一处理不改变已检查的路径几何或车尾清门条件。最终安全制动和用户取消仍优先于舒适约束。
仿真正常周期在 0.001 s 至 0.25 s（不含上界）之间时，平滑计算使用真实 ROS 时间间隔，
避免将较长周期截成 0.10 s 后产生虚假的加速度状态。重复、倒退、过短或过长的控制周期
撤权停车，状态记录 `clock_fault=control_interval` 及实际 `elapsed_s`；不通过延长动作时效
继续积分旧命令。同一 ROS 时刻的门准入预估只预测下一名义 0.05 s 周期，不推进状态，
仍须经过后续实际输出的独立制动检查。非仿真保留原周期计算规则。

主动接管也预留减速余量。持续新鲜的强转向输入在接管转交规划器时保留摇杆控制，直到
当前授权的新动作或已检查的门跟踪器可接续；松杆、输入过期、前方停车、门等待或脱困会
撤销交接状态。该衔接不延长规划动作时效，也不允许复用旧 NeuPAN 输出。

主要调参在 `config/neupan_wheelchair.yaml`：`robot.vertices` 必须覆盖整车，`max_speed`、`max_acce` 与底盘一致，`pan.dune_max_num` 控制点云规模，`step_time` 和 `receding` 控制规划频率与前视长度。

`adjust.d_min` 和 `adjust.d_max` 均为 0.10 m，避免优化器在已满足间距时继续奖励远离墙面。
沿墙参考独立保持 0.12 m 的车身边缘目标间距；最终制动检查仍独立执行。上游默认
`d_max=1.0` 与贴墙行驶不匹配，即使 DUNE 距离预测准确，也可能造成明显离墙和摆动。

## 安装与训练

上游当前主线要求 Python 3.10；ROS Noetic 使用 Python 3.8 时固定使用
`py38` 分支（当前提交 `70991f0d96b7a15135ba02ea8ad3f3090ff0926e`）。在 Noetic
容器中执行：

```bash
python3 -m venv /opt/neupan-venv
. /opt/neupan-venv/bin/activate
git clone --branch py38 --depth 1 https://github.com/hanruihua/NeuPAN /tmp/NeuPAN
pip install --upgrade pip
pip install -r /tmp/NeuPAN/requirements.txt
pip install -e /tmp/NeuPAN
```

训练必须显式执行，不要在导航 launch 中触发。训练 YAML 的 `robot` 轮廓应覆盖轮椅，推荐顶点
`[[-0.25,-0.40],[0.97,-0.40],[0.97,0.40],[-0.25,0.40]]`，并配置 `kinematics: diff`。
准备好训练参数后运行：

```bash
python3 scripts/train_neupan_dune.py \
  catkin_ws/src/smart_wheelchair_safety/config/neupan_wheelchair.yaml \
  --output /models/wheelchair-dune --epochs 5000 --data-size 100000
```

训练默认可在 CPU 上运行，但完整数据集和 5000 epoch 需要较长时间；先用较小 `data_size` 和
`epoch` 做冒烟检查，再使用完整参数生成 `.pth`。权重存放在工作区外，并通过
`dune_checkpoint:=/absolute/path/model_*.pth` 传给 launch。

训练输出目录必须尚不存在。`pan.dune_checkpoint` 不设置时，上游使用空模型进行显式训练；
不要把该字段设为空字符串（上游会把它解析成目录），也不要在 ROS 加载的 YAML 中设置为
`null`（ROS 参数服务器不能序列化它）。运行时由 launch 的 `dune_checkpoint` 参数提供权重。

在 ARM64 / Python 3.8 上，本次验证使用 `torch==2.4.1`、`numpy==1.24.4`、
`scipy==1.10.1`、`cvxpy==1.5.2`、`cvxpylayers==0.1.6`、`diffcp==1.0.23`。
`gctl==1.2` 导入时还需要系统包 `python3-tk`。如果 `diffcp` 的隔离构建尝试编译旧版
NumPy，可先安装 `pybind11`、`wheel`、`setuptools>=61`，然后在已具备 NumPy / SciPy 的
专用环境中使用 `pip install --no-build-isolation diffcp==1.0.23`。

整套仿真需要显式打开 NeuPAN，单独启动桥接节点不会打开协调器的采用开关：

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 roslaunch smart_wheelchair_gazebo sim.launch \
  use_neupan:=true dune_checkpoint:=/models/wheelchair-dune/model_5000.pth
```

启动后确认 `/unified_control_node/use_neupan` 为 `true`。`/neupan/status` 在摇杆回中、
参考路径缺失或传感数据过期时输出 `invalid input` 属于预期停车行为；仅存在 ROS 节点、
话题或备用跟踪器能行驶，不能证明 NeuPAN 的动作被实际采用。

### 普通摇杆与新规划衔接

辅助开启时，普通倒车和原地转向也按实际控制周期限制两轴加速度与 jerk。摇杆目标是软目标，回收已有加速度时可能短暂越过目标；固定倒车物理下界仍为 −0.4 m/s，角速度边界仍为 ±0.65 rad/s，最终完整制动检查保留。已有倒车惯性在切换正向意图时持续平滑回收；纯正向行驶与门口等待的原有限制不变。

新鲜的非正向意图切换为正向、且尚无授权参考动作时，只允许一次从实际输入 receipt 起小于 0.25 秒的初次规划等待。期间使用零速度目标和当前状态受 guard 检查地减速，状态来源为 `transition_stop`；不复用旧规划，heartbeat 或参考更新不能延长窗口。匹配的新动作到达立即结束等待；回中、取消、时钟/输入故障、恢复模式及 guard 拒绝仍按原规则停车，窗口耗尽仍为 `planner_timeout`。这一衔接不保证在不可行初态或持续规划失联时保持舒适性。

仿真控制对重复回调采用保守去重：只有上一成功 `clear` 输出的时间戳、已消费输入、授权和参数均未变化，且输入与时钟仍新鲜时，才忽略同一仿真时刻的重复计算，不积分、不重发命令、不撤销授权。任何新输入、取消、参数变化、时钟冻结或回退仍保留原停车保护；该行为不扩大任何 TTL，也不保证所有追赶回调都能被忽略。
