# GUI 扫描双色与车身遮挡验收

左侧青蓝 `(0.1, 0.65, 1)`、右侧橙色 `(1, 0.35, 0)`，不透明度均为 0.08。仅在既有 Gazebo VisualPlugin 中修改显示。

每帧在原生 LaserVisual 更新后，将扫描顶点与 base_link 下车身 box 外观求线段交点，截断到最近表面；使用部件的完整位姿和三维尺寸，排除自身雷达外壳。当前固定车身细节为 box；低处轮子不在激光平面上。未增加碰撞几何、ROS 订阅或修改传感数据。不是按整车二维外接矩形屏蔽后半圈，也不是对乘员、附件或未来 mesh 模型的完整仿真。

## 实际雷达遮挡核查

`unified_control_node.py:on_scan` 将采集时落在车体轮廓内的回波移除，安全检查保留有效全角度扫描，规划仍使用侧前约 200° 视场。这是自体回波过滤，不是完整的盲区/遮挡建模。

模型的 Gazebo ray 传感器依赖碰撞体，而靠背、座椅等细节部分只有 visual。因此不能将当前数据链路描述为“已完整考虑车身遮挡”。本轮经用户明确限定，只裁剪 GUI；不把显示裁剪结果送入安全控制，不宣称改善了实际感知覆盖。

## 验证结果

- 测试先行：新增不带 collision 的测试车身方块，旧插件因扫描显示穿过方块而失败。
- 修复后：两侧测试后向扫描显示在 0.25 m 处截断，ROS 同束距离仍大于 0.5 m。向前无遮蔽的扫描保持原范围，高于和低于激光平面的测试方块均不误遮挡。场景模型带 0.45 rad 偏航，验证坐标转换。
- 完整原生渲染通过：左右各 82 帧扫描未改变，频率各约 10 Hz，后摄 124 帧有效图像；门洞绿色线段、超时、槽位上限及 60 个轨迹槽位检查继续通过。
- 完整构建及 catkin 回归：384 项，0 错误、0 失败、0 跳过。
- 原生更新顺序依据 [Gazebo 11 LaserVisual 源码](https://github.com/gazebosim/gazebo-classic/blob/gazebo11/gazebo/rendering/LaserVisual.cc)，GUI 裁剪回调在其更新回调注册之后注册，避免新扫描覆盖裁剪结果。
