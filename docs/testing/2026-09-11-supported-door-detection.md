# 门洞候选修复与 Gazebo 绿色显示验收

状态：最终单场景闭环矩阵、原生渲染与 GUI 恢复验收通过。环境为 Ubuntu 20.04、ROS Noetic、Gazebo 11，工作分支 `feature/ros1-noetic-migration`。

## 现场问题与修复

西北竖门前的实际扫描被提取成多个共面墙片段。旧算法先在候选间隙两端各裁去 5 cm，再要求第三段墙面重叠超过 8 cm；紧贴门框的约 12.4 cm 短片段因此被忽略。同一门洞产生四个候选，约 1.349 m 的偏宽候选先被确认，约 1.225 m 的可规划候选因宽松的跟踪匹配被丢弃。确认后的几何不再刷新，反复沿同一偏宽目标搜索，造成 `door_wait` 零输出。

- 现在直接检查完整间隙中的墙面重叠，并在双雷达结果中只合并几何近乎一致的重复候选。没有按地图坐标指定门洞，也没有通过降低安全距离来放行。
- 已确认门洞可以接受有支撑的、明显向内收窄的门框更新；不因遮挡而随意放大门宽，不跟随同宽墙面匹配不断漂移。
- 对正阶段出现这样的更新时，旧缓存路径和未完成规划的代次同时失效，取消旧指令，停稳后重新规划；不把旧后台结果交回控制。
- 显示确认与导航候选分开。持续的回中摇杆消息仍取消导航辅助，但不会反复擦除门洞显示的连续观测历史。

实测门宽不等于检测宽度：受可见边缘与遮挡影响，保存点云中修复后的估计仍约为 1.225 m；可行路径最终针对完整安全点云检查，而非只依赖这个门宽数值。

## 显示语义

`/shared_control/door_detections` 使用 `geometry_msgs/PolygonStamped`，父坐标为与 Gazebo 世界重合的 `odom`，每两个端点组成一个检测门洞。连续两次观测确认的 0.92–1.50 m 窄门显示为绿色线段，世界高度 0.12 m、直径 0.03 m，最多 32 条。

显示按当前模型位姿反变换到父节点，避免跟随轮椅平移/旋转。无观测或传感数据过期时发布空结果；Gazebo 端同时使用接收时间及消息时间，超过 0.6 s 不再显示。线段仅供 GUI 观察，没有碰撞体，也不进入相机渲染。绿色不表示已经保证整车可以通过。

## 已完成的验证

- 新增保存现场点云的自动回归 `test/fixtures/nw_door_wait_capture.json`。改前候选数为 4，改后正序/逆序输入均为 1，并能生成全点云净空检查通过的路径。
- 短门框片段、重复检测、向内更新、缓存及后台路径失效、回中消息、显示坐标与过期清除均有回归。最终 catkin 当前为 383 项，0 错误、0 失败、0 跳过（含 nose 与 rostest 对部分几何用例的重复执行）。
- 不重置 GUI 位置的前推杆试验完成过门：约 20.303 s，车尾完整越过西北竖门，车体扫掠与地图碰撞体无重叠，松杆后新鲜实测停车。测试前后轴位姿约 `(0.509, 3.056, 2.971 rad)`；原始 23° 偏角点云另用于离线回归。原位测试发生在后来追加的缓存失效/静止显示补丁之前，不能代替最终版本的闭环矩阵。
- 原生渲染完整检查通过：非零模型偏航下的世界坐标、绿色材质、线段尺寸、32 槽上限、无效输入拒绝、清空与超时均正确；原有 60 条轨迹槽位反复显隐后保持稳定。左右各 76 帧扫描未改变，频率各为 10 Hz，113 帧有效相机图像；检查了 GUI-only 标志与原有雷达 alpha=0.035。相机验证为帧与可见性标志检查，不是逐像素比较。

## 失败与重测记录

初始基线 372 项出现两项时间敏感失败，独立复测均通过；最终版本完整 383 项通过。未改变生产环境的 100 ms 里程计新鲜度或其他制动阈值来迁就测试。

早期多个 Gazebo 实例同时运行时出现 `stale_input`、`planner_timeout` 和停滞；三实例 CPU 总使用率曾约 700%。部分批次因此停止，原记录保留。v12 北侧完整 42 例为 39/42，三次失败不删除、不替换；其中一个大角度用例在长时间数据间断后丢失辅助、转入沿墙，最终停在前墙。后续改为单场景、每轮独立目录。v12 南侧单场景批次因修复静止显示而中止，不作为完整验收。

最终 v13 在固定源码下重新运行全六门、双向、`0/±15/±30/±45°` 共 84 例；另增加左右偏离门中心 25 cm、进入方向 `0/±15°` 共 36 例，并检查 20 个路口与 24 个门框前后向低净空脱困位姿。所有过门失败均进入各自批次的分母。

## 最终结果

全地图六门、双向七角度的最终单场景矩阵：84/84，100%，每个门洞均为 14/14。左右各偏离门中心 25 cm 的进入方向补充各为 18/18，过门累计 **120/120，100%**，达到本轮仿真测试通过率超过 90% 的要求。路口 **20/20**，门框前后向低净空脱困 **24/24**。标准过门矩阵最长连续近停约 1.15 s；脱困最小退出距离约 0.532 m，最大向障碍侧位移约 0.233 mm，全部通过碰撞及停车检查。

最终重新构建并执行 catkin：**383 项，0 错误、0 失败、0 跳过**。完整原生渲染检查再次通过。GUI 已恢复到原位前推杆试验开始前的模型位姿；真实 HTTP 回中摇杆连续发送期间，最后 20 次观测中 20 次正常显示门洞，原始及输出速度均为零，实测停车、双侧 721 束/10 Hz 雷达及 640×360 相机均通过检查。已查看 GUI 截图，前方门洞有绿色横线；只保留 GUI 仿真实例运行。

逐例结果、批次配置及已核对的源码 SHA-256 保存在 [机器可读验收记录](2026-09-11-supported-door-results.json)。原始日志及 GUI 截图位于本地 `.superpowers/behavior/door-supported-v13-*`（不随 Git 跟踪）。渲染测试覆盖非零父位姿，尚未加入连续移动父模型的专门断言；插件每帧进行坐标反变换。未来时间戳未单独拒绝，但接收后 0.6 s 的独立超时仍生效。

## 复测

在独立的已启动 Noetic 仿真容器中运行，不与 GUI 或另一场景竞争资源：

```bash
python3 catkin_ws/src/smart_wheelchair_gazebo/test/check_door_matrix.py --output /tmp/door-full-new
python3 catkin_ws/src/smart_wheelchair_gazebo/test/check_door_matrix.py --directions in --angles -15 0 15 --lateral-offset 0.25 --output /tmp/door-offset-left-new
python3 catkin_ws/src/smart_wheelchair_gazebo/test/check_door_matrix.py --directions in --angles -15 0 15 --lateral-offset -0.25 --output /tmp/door-offset-right-new
```

每例仍为 35 s，连续停止超过 3 s 判失败；检查指定门洞穿越、车尾完整越门、按 5 mm 扫掠采样的整车轮廓与地图碰撞体保留 2 cm，以及松杆后的新鲜停车数据。几何无重叠不等同于接触传感器测量；这些是静态平面仿真结果，不是实车安全认证。
